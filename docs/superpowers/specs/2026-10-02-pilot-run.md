# End-to-end synthetic pilot run

Status: authorised by the operator on 2 October 2026 as the last part of the pilot
preparation. It runs a locked pilot from collection start to the end of its live
window against a deterministic synthetic provider. No platform is contacted and
every figure is *simulated*: it tests the machinery, not the world.

## Purpose

The schedule, the replay rule, the quota ledger, the cost projection and the pilot
lock were each tested on their own. The run puts them together the way a pilot
would use them, so that the guarantees hold in combination: no call before the
lock or before discovery, every call debited first, a clean stop at the ceiling,
and an executed cost that can be set against the projection.

## Modules

| Item | Delivers |
|---|---|
| `SimulationClock` | A clock the run advances and that never moves backwards; the ledger reads the same clock |
| `SyntheticProvider` | Seeded videos for the sampled channels and seeded threads per video, drawn from the volume assumptions; newest-first listing as of the clock, or as of the snapshot a walk began on; every call logged |
| `PilotBudget` | The pilot's ceiling across days, on top of the ledger's daily reservations; it counts a call exactly when the ledger wrote a debit for it |
| `run_pilot`, `render_run` | The run and its deterministic Markdown report |

## Run

| Step | Behaviour |
|---|---|
| Start | Refused without a verified lock, under another quota policy, with a provider built from another lock, with a ledger or provider on another clock, or after collection start; the clock moves to collection start |
| Discovery | At every registered tick in the live window, each sampled channel's playlist is listed newest first until the newest video already seen or a video from before collection start |
| Polls | Each discovered video's jobs come from the registered schedule; jobs due after the live window are counted, not run; a poll stops at the newest thread already seen or the page cap |
| Retrieval | Once a day, the history span is enumerated per channel and every thread page of its videos read, within the retrieval reservation. Each walk pages through the snapshot it began on, so a walk resumed the next day reads no page twice; a refused call ends the day's session |
| Failures | A provider error or network error is counted, stays spent, and the run carries on; a failed retrieval page is retried after the rest of the queue, and a session ends when every queued page fails in turn. Other exceptions are faults and propagate |
| Accounting | Only debits written during the run are reported, whatever the ledger held before |
| Ceiling | The next call that would pass the ceiling stops the whole run cleanly |

## Executed and projected

For the example pilot (12 channels, 14 live days, 28 history days, seed 11) the
run spends 19,099 units: 8,965 live against a projected 10,752, and 10,134 for
retrieval against 10,152 (*simulated* against *calculated*). The projection is a
steady state. A finite live window leaves 2,876 later poll jobs unrun, and history
videos younger than their thread-arrival window have fewer threads at retrieval,
so the executed figures are lower. Discovery matches the projection exactly.

## Acceptance tests

| Contract | Named test in `tests/collectors/test_pilot_run.py` |
|---|---|
| No run without a verified lock, the locked quota or the registered start | `test_pilot_refuses_to_start_without_a_valid_lock` |
| No call before the lock, and no live poll before its video's actual discovery | `test_no_call_precedes_the_lock_or_discovery`, `test_failed_calls_stay_spent_and_the_run_carries_on` |
| Ledger units equal the calls made | `test_ledger_units_equal_pilot_calls` |
| Failed calls stay spent and the run carries on | `test_failed_calls_stay_spent_and_the_run_carries_on` |
| The run is deterministic for a seed | `test_pilot_run_is_deterministic` |
| Executed cost against the projection | `test_executed_cost_matches_projection_on_synthetic_volumes` |
| A walk pages through its snapshot; a snapshot never passes the clock | `test_provider_pages_through_the_snapshot_a_walk_began_on` |
| Retrieval across sessions reads every page once and counts every thread once | `test_retrieval_across_sessions_reads_each_page_once` |
| A busier world stops cleanly at the ceiling | `test_pilot_stops_cleanly_at_its_ceiling` |
| The report says the figures are simulated | `test_report_labels_figures_as_simulated` |

The provider's real paging across days is not documented (BACKTEST §D.4); the
snapshot is an assumption of the simulation, not a property of the platform.

Outside this increment: a `pilot` command, the live latency λ (which needs real job
delays), refresh and deletion costs, and any recorded provider responses.
